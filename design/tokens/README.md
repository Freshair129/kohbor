# Kohbor design tokens

**Design version 1.0.0 · 11 November 2026 (Asia/Bangkok) · DEC-VISUALS proposal**

This package contains **248 authored tokens**: 74 primitives, 125 dark semantic decisions and 49 component aliases. Its generated CSS exposes 255 custom properties because each of the seven typography composites also exports a letter-spacing property. The package supplies reusable design decisions for Kohbor / เกาะเบาะ; native readability, safe areas and implementation acceptance remain open under the existing UX specification.

Import **kohbor.tokens.json** when a tool accepts the supported DTCG forms. The three authored token files share a merged namespace; importing a semantic or component file alone leaves references unresolved. Use **tokens.resolved.json** for consumers that cannot resolve aliases. The CSS adapter file is project configuration, not a DTCG token document.

## Build and verify

Run from the repository root with Python 3.10 or later. These tools use the standard library and make no network requests.

```bash
python tools/build_design_tokens.py
python tools/validate_design.py

python tools/build_design_tokens.py --check
python tools/validate_design.py --check
```

The build fails on duplicate JSON keys, unknown references, cycles, alias type mismatches, invalid supported value shapes, unsupported constructs or CSS name collisions. The validator then checks intended color pairs, authored geometry, typography/target proposals, generated-file equality, 13 deliberate invalid-input rejection cases and four exporter regression cases. Both `--check` commands are read-only with respect to deliverable files and exit nonzero on drift.

Regenerate the receipt after editing a token source or either tool. The receipt hashes exact source, tool and generated bytes and records a content-addressed validation revision. It has no changing timestamp or dependency on Git HEAD, so an unchanged source tree produces the same output before and after a commit.

## Format and importer boundaries

The source uses the `$type`, `$value` and reference value forms published in the [DTCG Format Module 2025.10](https://www.designtokens.org/tr/2025.10/format/) and [Color Module 2025.10](https://www.designtokens.org/tr/2025.10/color/). Those documents are Community Group reports, not W3C Recommendations. This exporter validates a deliberately bounded **project profile**; it does not claim complete DTCG importer conformance.

| Supported type | Authored representation | CSS export |
| --- | --- | --- |
| `color` | Numeric sRGB object with three components, alpha and matching six-digit fallback | Hex or fractional `rgb()` with alpha |
| `dimension` | Numeric `value` and `px` or `rem` unit | CSS length |
| `fontFamily` | One family name or an ordered family array | Quoted family list with generic families preserved |
| `fontWeight` | Numeric weight or supported DTCG weight name | Numeric CSS weight; DTCG names such as `semi-bold` resolve to numbers |
| `number` | Finite JSON number | Unitless number |
| `duration` | Nonnegative `value` with `ms` or `s` unit | CSS time |
| `cubicBezier` | Four coordinates with bounded x coordinates | `cubic-bezier()` |
| `shadow` | One color/offset/blur/spread object | Box-shadow value |
| `typography` | Family, size, weight, letter spacing and line height | Font shorthand plus a separate tracking property |

Whole-token curly-brace aliases, nested composite-member aliases and group type inheritance are supported. Unsupported input is rejected rather than partially imported: JSON Pointer `$ref`, group `$extends`, `$root`, the Resolver Module, embedded references inside strings, non-sRGB colors, `none` color components, shadow arrays, gradients and other composites. The custom metadata key `org.kohbor.design` describes this design export only; it freezes no application ID, domain, URI scheme or trust namespace.

No import into a third-party design tool has been verified. A consumer supporting an older draft may require an adapter for typed color/dimension objects or typography composites. Preserve the source forms and add an explicit exporter instead of rewriting source tokens into one vendor's format.

## Naming and alias hierarchy

Token names describe decisions, not routes or runtime state. All paths are dot-separated; the CSS names use a stable `--kb-` prefix.

| Source path | Generated CSS property | Consumer role |
| --- | --- | --- |
| `primitive.color.ink.900` | `--kb-primitive-color-ink-900` | Raw palette value |
| `semantic.color.surface.panel` | `--kb-color-surface-panel` | Surface meaning |
| `component.card.background` | `--kb-component-card-background` | Card styling |
| `semantic.typography.body` | `--kb-typography-body` | Body font shorthand |
| `semantic.typography.body` letter spacing | `--kb-typography-body-letter-spacing` | Body tracking |

The generated relationship remains readable:

```css
:root {
  --kb-primitive-color-ink-900: #121A21;
  --kb-color-surface-panel: var(--kb-primitive-color-ink-900);
  --kb-component-card-background: var(--kb-color-surface-panel);
}
```

Components should consume component or semantic properties. Introduce a primitive only when there is a reusable underlying decision; avoid hard-coded copies in component styles. Apply theme/preference attributes on the document root. Moving an override to a nested element requires redeclaring the relevant alias graph at that scope because inherited custom properties resolve where they are defined.

### Contrast contract

The receipt checks **146 intended pairs** across normal dark and increased-contrast modes. The current lowest normal-text pair is muted text on the hover surface at **4.541:1**. The lowest checked non-text pair is the strong border on the raised surface at **3.509:1**. The thresholds are 4.5:1 for normal text and 3:1 for the listed focus/interactive cues, compared before rounding, following [WCAG text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) and the [sRGB calculation method](https://www.w3.org/WAI/WCAG22/Techniques/general/G18).

Default borders are decorative. They do not meet the control-boundary target. A strong border against the hover surface is also below 3:1; identify a hovered row through its readable content or use a contrasting accent/focus boundary when the boundary carries meaning. Adding opacity, different backgrounds, images or new pairings requires another check. The receipt is not an interface-wide WCAG claim.

## Typography, spacing and geometry

The local font stack is `"Noto Sans Thai", "Noto Sans", "Leelawadee UI", "Tahoma", system-ui, sans-serif`. The separate design board bundles Thai and Latin Noto files for offline coverage; this token directory contains no font binaries and makes no CDN request. The first available registered or host font is used; Thai glyph coverage, shaping, fallback and actual weight availability must be inspected on the target environment.

| Style | Authored size | Line height | Weight |
| --- | --- | --- | --- |
| Body | 16px | 1.6 | 400 |
| Supporting | 14px | 1.6 | 400 |
| Label | 14px | 1.6 | 500 |
| Heading small | 20px | 1.3 | 600 |
| Heading medium | 24px | 1.3 | 600 |
| Heading large | 32px | 1.3 | 600 |
| Display | 48px | 1.2 | 600 |

Tracking is zero. Do not compress Thai line height or shrink individual strings to make a region fit. The 4px spacing scale has 13 steps (`--kb-space-0` through `--kb-space-12`). Radii are 8/12/16/24px and a pill value. Proposed targets are 44px by default and 36px for compact controls. The proposed focus treatment is a 2px ring with a 3px gap.

The fixed stage remains 1420 × 760; navigation occupies `(20, 20, 88, 720)` and the panel occupies `(120, 20, 1280, 720)`. Live-region coordinates are panel-local:

| Region | x | y | Width | Height |
| --- | ---: | ---: | ---: | ---: |
| Header | — | 0 | Panel width | 72 |
| Own hero/companion | 16 | 168 | 196 | 430 |
| Map | 228 | 168 | 616 | 430 |
| Five enemies | 228 | 84 | 616 | 72 |
| Four allies, excluding self | 228 | 610 | 616 | 94 |
| Reserved right region | 860 | 84 | 404 | 620 |

The map has 264,880 authored square pixels; the right region has 250,480. The validator checks containment, non-overlap, alignment, slot counts and the map's area priority. Runtime map stability within 1 CSS px across selection/tier changes still requires browser tests. Native window bounds, text after stage fitting and game HUD clearance still require Windows measurements. CSS pixels are authored units here, not measured Windows device pixels.

## CSS use

Load the generated stylesheet before component styles, then bind its properties deliberately. Importing tokens alone does not add keyboard behavior, visible focus, target sizing or accessible names.

```html
<link rel="stylesheet" href="./tokens/tokens.css">
```

```css
.control-surface {
  color: var(--kb-color-text-primary);
  background: var(--kb-color-surface-panel);
  font: var(--kb-typography-body);
  letter-spacing: var(--kb-typography-body-letter-spacing);
}

.primary-action {
  min-block-size: var(--kb-component-button-min-height);
  padding-inline: var(--kb-component-button-padding-inline);
  border: var(--kb-border-width-default) solid transparent;
  border-radius: var(--kb-component-button-radius);
  color: var(--kb-component-button-foreground);
  background: var(--kb-component-button-background);
  font: var(--kb-typography-label);
  transition: background-color var(--kb-motion-duration-fast)
    var(--kb-motion-easing-standard);
}

.primary-action:hover {
  background: var(--kb-component-button-hover-background);
}

.primary-action:active {
  background: var(--kb-component-button-pressed-background);
}

.primary-action:focus-visible {
  outline: var(--kb-focus-width) solid var(--kb-color-focus);
  outline-offset: var(--kb-focus-offset);
}
```

Reserve enough space so outlines are not clipped by bounded containers. Keep disabled explanatory text readable; do not apply the decorative disabled-opacity primitive to a parent containing required labels.

## Accessibility adapters

- **Increased contrast:** `prefers-contrast: more` strengthens text and borders. `<html data-kb-contrast="more">` explicitly enables that palette; `data-kb-contrast="standard"` bypasses the automatic preference mapping. Both variants are included in the static color-pair receipt.
- **Forced colors:** the generated media query maps colors to system values, preserves a distinct selected navigation foreground and removes panel shadow. These declarations take precedence over the app's increased-contrast preference. They do not disable the user's color adjustment. Actual WebView2/system rendering is not established by the token mapping.
- **Reduced motion:** `prefers-reduced-motion: reduce` and the explicit `<html data-kb-motion="reduced">` preference each set every semantic motion duration to `0ms`. An explicit normal setting does not override the operating system's reduced-motion preference. Consumers must use those durations and avoid independently hard-coded animation. The ordinary timing scale is 0/100/160/240ms. Motion values never govern observation freshness, native timers or delayed clearing of invalid data.

Transparent overlay scenes need their own composited contrast measurements. The default overlay backing token is opaque; a user-selected opacity changes that evidence requirement. No token value proves passive click-through, native focus safety, acoustic timing, live data correctness or resource/FPS compliance.
