# Risk admission (DEC-RISK-DETAIL draft)

**Status.** Agent draft for owner review. Nothing here is approved. Every number marked **[P]** is a team proposal that the owner must approve or change. A number marked **[I]** is inherited from the baseline (FEATURE-CATALOG, SDD section 6, ALERT-002/003/004) and is repeated here only so the rules are complete; this draft does not change it. Until the owner closes DEC-RISK-DETAIL, the score stays informational and the audible missing-gank cue stays unavailable (`AUDIBLE_MISSING_GANK_APPROVED = false` in `crates/kohbor-risk/src/admission.rs`).

This document extends the existing risk rules; it does not replace them. No separate risk specification existed before it: the formula lives in [FEATURE-CATALOG](../product/FEATURE-CATALOG.md) ("Missing-time heuristic", "Hysteresis") and the guards in [SDD section 6](SDD.md). The fixtures that freeze it are under `fixtures/risk-admission/`, generated by `tools/gen_risk_admission_fixtures.py`.

## 1. Scope and what this draft does not do

- It defines, for one evaluation tick: the inputs, the per-hero absence state, the score, heading, coordinated-motion group, death window, ETA, thresholds, cooldowns, re-arm, correction and the exact reason the cue stays silent.
- It does not create a positional-evidence source, does not predict paths through fog and does not use time decay to correct anything (DEC-RISK-DETAIL safe interim; SDD section 6).
- It does not wire anything into the host, the critical path or the audio engine. That is S6-4 after approval, and it also needs DEC-CRITICAL-MEDIA.
- It does not replace the current anonymous-count `RiskEngine` (Danger Meter and experimental visual events, MVP-1). Section 10 compares the two.

## 2. Inputs (one tick = one admitted capture frame)

Evaluation is event-driven: one tick per admitted minimap frame. All times are local monotonic milliseconds. Map coordinates are minimap milli-units, `x` and `y` in 0..=1000 (the `kohbor-vision` `MapPoint` convention), Euclidean distance.

| Input | Type | Source | Unknown means |
| --- | --- | --- | --- |
| `t_ms` | u64 | frame admission time | — |
| `coverage` | valid / stale / unavailable | `kohbor-capture` coverage | not valid → interrupt (section 3.4) |
| `sightings[]` | track, `hero` (certified id or none), `x`, `y` | `kohbor-vision` admitted sightings | a sighting without a certified id is anonymous and never contributes |
| `own.fresh` | bool | GSI age ≤ 2000 ms **[I]** | false → no cue |
| `own.in_match` | bool | GSI `map.game_state` = GAME_IN_PROGRESS | false → no cue (pregame, post-game) |
| `own.alive` | bool | GSI `hero.alive` | dead → no cue (section 5) |
| `own.paused` | bool or unknown | GSI `map.paused` (seen in `crates/kohbor-gsi/tests/captured/in-progress-paused.json`) | paused or unknown → interrupt and no cue |
| `own.kills`, `own.assists` | integer or unknown | GSI `player.kills`, `player.assists` (admitted in `kohbor-gsi`) | unknown → no cue (section 5) |
| `own.map_pos` | `x`,`y` or unknown | **no source today** (see section 6.4) | unknown → no cue when the player-relative gate is on |
| `media_ready` | bool | critical-media readiness (DEC-CRITICAL-MEDIA) | false → no cue |

`own` itself may be absent (no GSI). That is the same as `own.fresh = false`.

## 3. Per-hero absence state

### 3.1 States

Each certified enemy hero is in exactly one state: `NeverSeen`, `Visible`, `Missing`, or `Interrupted`. Anonymous sightings change nothing here.

- `NeverSeen → Visible` on the first certified sighting. A hero never seen is never a contributor ("previously observed enemy", FEATURE-CATALOG).
- `Visible → Missing` on the first valid tick in which the hero is not sighted. `vanish_ms` = the time of its last sighting. The pre-vanish heading (section 4.2) is computed at this moment from the visible history and frozen for the episode.
- `Missing → Visible` only by **confirmed continuous reappearance** (3.2). This closes the absence episode and re-arms the hero (clears its `notified` flag).
- any → `Interrupted` on an interruption (3.4). `Interrupted → Visible` also needs confirmed continuous reappearance.

### 3.2 Confirmed continuous reappearance

A reappearance run starts at the first tick a `Missing` or `Interrupted` hero is sighted again and continues while it is sighted on every following tick. A tick without a sighting ends the run with no effect. The run confirms when both hold:

- at least **3** sighted ticks in the run **[P] `REAPPEAR_MIN_FRAMES = 3`**, and
- `t_latest − t_first_of_run ≥ 500 ms` **[P] `REAPPEAR_MIN_MS = 500`**.

On confirmation the hero becomes `Visible` and its visible history restarts with the run's sightings. An unconfirmed run (a blip, one noisy frame) does not end the episode, does not move `vanish_ms` and does not re-arm the hero (ALERT-004 failure behaviour).

### 3.3 Missing time

For a `Missing` hero, `s = (t_ms − vanish_ms) / 1000` seconds. Only `Missing` heroes have a missing time. `Interrupted` heroes have none (unknown, not zero).

### 3.4 Interruption (observation gap, pause)

At the start of a tick, if any of these holds, every hero that is `Visible` or `Missing` becomes `Interrupted`, its visible history is cleared and its heading is dropped:

- `coverage` is not valid on this tick;
- the gap since the previous tick is greater than **2000 ms** **[I] `OBSERVATION_GAP_MS`** (VISION-002);
- `own.paused` is true or unknown.

An interruption also ends every reappearance run. `notified` flags and all cooldown history survive an interruption (SDD section 6: "Preserve cooldown history across capture gaps"). A still-missing hero after a gap is not a contributor until it is seen again and confirmed: the baseline is rebuilt, nothing is inferred.

The visible history keeps at most the last 5 minutes **[I]**.

## 4. Score (informational)

### 4.1 Base risk per hero **[I]**

`ramp_start_s = 5`, `peak_s = 12`, `peak_risk = 0.70`, `decay_per_s = 0.03`, `floor = 0.10`:

- `s < 5`: `r = 0`
- `5 ≤ s ≤ 12`: `r = ((s − 5) / 7) × 0.70`
- `s > 12`: `r = max(0.70 − (s − 12) × 0.03, 0.10)`

A non-finite or negative `s` gives unavailable, never a number (ALERT-002 failure behaviour).

### 4.2 Pre-vanish heading **[P]** (exact rule; the multiplier itself is **[I]**)

Take the hero's visible sightings with `at_ms` in `[vanish_ms − 1500, vanish_ms]` **[P] `HEADING_WINDOW_MS = 1500`**. The heading is **valid** only if:

- there are at least **3** such sightings **[P] `HEADING_MIN_SIGHTINGS = 3`**;
- the earliest is at least **500 ms** before the last **[P] `HEADING_MIN_SPAN_MS = 500`**;
- the displacement from the earliest to the last is at least **20** milli-units **[P] `HEADING_MIN_DISPLACEMENT = 20`** (2 percent of the map side; a standing hero has no heading).

Then `h = p_last − p_earliest`. Otherwise the heading is unknown: the score uses the neutral multiplier 1.0 and the hero cannot join a coordinated group (6.1).

Score multiplier **[I]**: `m = 1 + clamp(cos(h, c), −1, 1) × 0.22` where `c = (500, 500) − p_last` (toward map centre). If `|c| < 20` **[P] `CENTER_DEADZONE = 20`** the direction to centre is undefined and `m = 1.0`. Then `r = clamp(r_base × m, 0, 1)`.

### 4.3 Aggregate **[I]**

Contributors = `Missing` heroes with `r > 0`. `R = 1 − Π(1 − r_i)`. With at least two contributors, `R = min(R × 1.15, 1.0)`. With no contributor, `R = 0`. The same function applied to a subset gives a group score (6.3). `R` is a labelled heuristic, not a probability (ALERT-002).

### 4.4 ETA **[I] per hero, [P] aggregation**

Per hero: `eta_i = max(12 − s_i, 1)` seconds, labelled **estimated** **[I]**. It is a time-since-vanish reference, not a distance or path estimate. Group ETA = `min(eta_i)` over the group (the soonest member) **[P]**. No speed, path or distance-based ETA is derived: that would be path prediction.

## 5. Session guards and death windows

### 5.1 Own hero

- Own dead: audible admission is blocked while `own.alive` is false and for **5000 ms** after the first alive tick (respawn) **[P] `OWN_RESPAWN_GRACE_MS = 5000`**.
- Own-death window: a hero whose `vanish_ms` falls inside `[death_ms, respawn_ms + 5000)` is not eligible for audible admission for that episode. The minimap keeps allied vision while the player is dead, so absence tracking and the score continue; only the cue is withheld, and nothing is replayed after respawn.
- Own state missing, stale or out of match: blocked; tracking continues. Death and respawn are taken only from fresh, in-match own state: a stale or out-of-match tick neither starts nor ends a death window, and the respawn time is the first fresh in-match tick with `alive` true after a fresh dead tick.

### 5.2 Enemy deaths (kill participation window) **[P]**

No admitted source tells Kohbor that an enemy hero died: the minimap cannot tell death from fog, and the player GSI carries no enemy roster. Two enemies killed together vanish together, which would look like a coordinated disappearance. The available evidence is the local player's own kills and assists:

- If `own.kills + own.assists` increased on any tick within **±3000 ms** of any group member's `vanish_ms` **[P] `KILL_PARTICIPATION_WINDOW_MS = 3000`**, the group is blocked (`kill_participation`).
- If kills or assists are unknown on the current tick, or were unknown on any tick from `min(vanish_i) − 3000 ms` up to the current tick, the cue is blocked (`kill_data_unknown`): an increase hidden in a gap cannot be ruled out. An increase is measured against the last tick on which both were known.
- Deaths the player did not take part in are not detected. This is a known residual false-positive source (section 9).

The previous "death discount" on the score is **not** introduced: no admitted death source exists, so the score has none (`fixtures/risk-golden.json` already states "no death discount").

## 6. Coordinated-motion admission

### 6.1 Candidates

A hero is a candidate when it is `Missing`, its heading is valid (4.2), it is not `notified` in its current episode, and its `vanish_ms` is outside every own-death window (5.1).

### 6.2 Group

A group is a set of at least **2** candidates **[P] `COORD_MIN_MEMBERS = 2`** in which **every pair** satisfies:

- `|vanish_i − vanish_j| ≤ 3000 ms` **[P] `COORD_VANISH_WINDOW_MS = 3000`** (equal to the current `COORDINATED_WINDOW_MS`);
- `|p_last_i − p_last_j| ≤ 120` milli-units **[P] `COORD_RADIUS = 120`**;
- `cos(h_i, h_j) ≥ 0.5` (headings within 60 degrees) **[P] `COORD_HEADING_COS = 0.5`**.

and the group is fresh: `t_ms − max(vanish_i) ≤ 15000 ms` **[P] `COORD_MAX_AGE_MS = 15000`**.

With at most five enemies, all subsets are checked. The chosen group is the largest; ties go to the higher group score, then to the lexicographically smallest sorted list of hero ids.

### 6.3 Gate order (one tick)

The gate returns the first failing reason, in this order, or `admit`:

1. `not_in_match` — `own` absent or `own.in_match` false
2. `gsi_stale` — `own.fresh` false
3. `own_dead_or_grace` — section 5.1
4. `paused_or_unknown` — `own.paused` true or unknown
5. `coverage_invalid` — coverage not valid on this tick
6. `own_position_unknown` — player-relative gate on (6.4) and `own.map_pos` unknown
7. `kill_data_unknown` — section 5.2
8. `no_group` — no group per 6.2 (this includes: no certified missing hero, headings unknown, too far apart, vanished too far apart in time, opposite directions, group too old)
9. `not_toward_player` — 6.4
10. `too_far` — 6.4
11. `kill_participation` — section 5.2
12. `below_danger` — group score `< 0.65` **[I] medium sensitivity** (`≥ 0.85` low, `≥ 0.50` high)
13. `global_cooldown` — less than **30 s** since the last admitted cue **[I] ALERT-004**
14. `contributor_cooldown` — a member had an admitted cue less than **60 s** ago **[I] ALERT-004**
15. `media_unready` — critical media not ready (DEC-CRITICAL-MEDIA)

On `admit`: emit `would_admit {members, score, eta_s}`; set every member `notified`; record the global and per-member cue time; add the members to the alert latch. While `AUDIBLE_MISSING_GANK_APPROVED` is false, the production decision for every tick is `unavailable(decision_open)` and `would_admit` exists only in the proposed evaluator and the fixtures.

### 6.4 Player-relative gate **[P] — owner choice**

`PLAYER_RELATIVE_GATE` decides whether the group must be heading toward the local player:

- Group heading `H` = sum of the members' unit headings. Centroid `g` = mean of the members' last positions. `d = own.map_pos − g`.
- `not_toward_player` if `|d| ≥ 20` and `cos(H, d) < 0.5` **[P] `TOWARD_PLAYER_COS = 0.5`** (or `|H| = 0`).
- `too_far` if `|d| > 250` milli-units **[P] `PROXIMITY_RADIUS = 250`** (a quarter of the map side; a static distance from the last admitted sighting, not a path).

**Option A (proposed default): gate on.** Fewer cues for groups moving elsewhere on the map. Consequence: the cue stays silent (`own_position_unknown`) until an own-position source is admitted. The captured GSI payloads in `crates/kohbor-gsi/tests/captured/` carry no `hero.xpos`/`hero.ypos`; whether the player GSI sends them is UNVERIFIED, and turning world coordinates into minimap coordinates needs map bounds (DEC-GAME-DATA). Detecting the own icon on the minimap would need a detector (DEC-MODELS).

**Option B: gate off.** Steps 6, 9 and 10 are skipped. The cue means "a group of enemies moved together and vanished", wherever it is on the map. Usable as soon as certified identities exist; more cues that do not concern the player.

Fixtures cover both: the default traces use option A, and the `opt-b-*` traces use option B.

## 7. Episodes, cooldowns, re-arm and correction

- One cue per absence episode: a `notified` hero is not a candidate until confirmed reappearance re-arms it **[I]**. Cooldown expiry alone never re-arms (ALERT-004).
- Global 30 s and per-contributor 60 s **[I]**. Cooldown history survives gaps, pauses, own death and enable/disable.
- A blocked tick changes nothing: a group blocked by `global_cooldown` or `media_unready` may admit on a later tick while it is still fresh (6.2).
- **Latch and correction.** The latch is the set of heroes in admitted cues not yet cleared. A latched hero leaves the latch when its reappearance is confirmed (it does not rejoin the latch if it vanishes again). When the last latched hero has left, the latch clears. In the same tick, if the session guards 1–5 pass and the aggregate score over all current contributors is `< 0.40` **[I] medium** (`< 0.50` low, `< 0.30` high; equality is not below), emit `correction_would_admit`; otherwise emit `latch_cleared_silent`. When a latched hero is interrupted, the latch clears with `latch_cleared_silent`. Time decay alone never emits a correction (SDD section 6).

## 8. Unknown means no cue

The cue is silent, with the reason from 6.3, when any of these is unknown or not admitted: own GSI (absent, stale, out of match), own alive state, pause state, kills/assists, own map position (option A), coverage, hero identity (anonymous tracks never contribute), heading (a hero without a valid heading never joins a group), missing time after a gap, critical-media readiness. No default value stands in for any of them.

## 9. What is unverified and what can still go wrong

- Every **[P]** number is a desk proposal. None was measured on recorded or live matches. The warning-quality harness (S6-5, ±8 s window) and labelled sessions are needed before anyone can claim precision or recall.
- Latency: with neutral headings, two heroes reach the 0.65 danger threshold about 8.4 s after vanishing, three heroes about 7.4 s (inherited formula). A gank faster than that gets no cue. Changing the formula is an owner decision, not part of this draft.
- Enemy deaths the player did not take part in, illusions, invisibility runes and ward expiry over a moving group can still look like a coordinated disappearance.
- The heading rule needs at least 3 sightings in 1.5 s, so it needs a capture rate of at least about 2 fps while the heroes are visible. The real rate is measured, not assumed (DEC-RESOURCE-BUDGET).
- Timing of GSI `kills`/`assists` updates relative to the minimap frame is UNVERIFIED (DEC-NATIVE-EVIDENCE).

## 10. Relation to the current code

`kohbor_risk::RiskEngine` (MVP-1) works on anonymous visible counts. Its `RiskAlert` is an experimental visual event, not audio. It fires on a two-count drop that holds for more than 5 s, with no identity, heading, group distance, player-relative, kill or media check. `crates/kohbor-risk/tests/admission_fixtures.rs` replays every fixture through it and compares the result with `fixtures/risk-admission/current-engine-replay.json`: per fixture, the times of `RiskAlert` and whether they agree with the proposed admission (`same` when both are silent, or both fire the same number of times with each `RiskAlert` within 2000 ms of a `would_admit`; otherwise `differs`). The anonymous projection is: visible count = number of sightings on the tick (certified or not), `OwnGsi { alive, hp_pct: None, in_match, age_ms: 0 if fresh else 3000 }`, same coverage, no GSI events. Those records describe today's behaviour; they are not targets.

## 11. Fixture format (`fixtures/risk-admission/`)

`index.json` lists every fixture with `id`, `file`, `kind` (`table` or `trace`), `rule` (section of this document), `expect` (`admit`, `silent` or `table`). Each trace file holds:

- `params_override` (optional): parameter names from the table in section 12 with replacement values (used by `opt-b-*` traces for `PLAYER_RELATIVE_GATE = false`).
- `ticks[]`: `t_ms`, `coverage`, `own` (null or `fresh`, `in_match`, `alive`, `paused`, `kills`, `assists`, `map_pos`), `media_ready`, `sightings[]` (`track`, `hero` or null, `x`, `y`).
- `expected.events[]`: `t_ms`, `kind` (`would_admit`, `correction_would_admit`, `latch_cleared_silent`), `members`, `score`, `eta_s`.
- `expected.probes[]`: `t_ms`, `reason` (the 6.3 reason, or `admit`), `score_all` (number, or null when coverage is not valid): one probe on the first tick and on every tick where the reason changes.
- The anonymous-count replay results live in one file, `current-engine-replay.json` (section 10).

Synthetic hero ids are `enemy_1` to `enemy_5`; no real hero, player or match data is used. Numbers compare with absolute tolerance 1e-6.

## 14. Interpretations frozen by the fixtures

Where the text above left a choice, the generator took the reading that keeps the cue silent. The fixtures freeze these readings; they are part of this draft and go to the owner with it.

- An interruption (3.4) applies before the tick is evaluated, and that tick's sightings are discarded: the new baseline starts on the next uninterrupted frame.
- Unknown `own.alive` is treated as `own_dead_or_grace`; unknown `media_ready` as `media_unready`.
- Two certified sightings of the same hero on one tick: the smallest `(track, x, y)` is kept, so duplicates cannot create heading samples.
- An own-death window starts on the first observed dead tick and ends at the first alive tick plus the grace; a vanish inside it excludes that episode for good.
- The score of a tick is computed after that tick's state transitions, so an interruption tick has no contributors (and `score_all` is null when coverage is not valid).
- Parameters out of range (a threshold outside [0, 1], revision not below danger, a negative duration or radius) are rejected by `Params::set`; the evaluator never runs with them.
- Time arithmetic saturates; a tick whose time is not after the previous tick is an interruption.
- The non-finite input of the score table is written as the string `"NaN"` because JSON has no NaN.
