Task: MVP2-ASSETS, round 2. Evidence: source, synthetic tests, and **one local
read-only probe invocation** on 2026-11-14. This is not live-match, visual-match,
CV-accuracy, FPS, or release evidence. The lead approved retaining the round-1
implementation as an exception to strict test-first sequencing.

## Implementation and API

```rust,ignore
let vpk = Vpk::open(game_root.join("game/dota/pak01_dir.vpk"))?;
let entry = vpk.find("panorama/images/heroes/npc_dota_hero_lion_png.vtex_c");
let bytes = vpk.read(&entry.ok_or(/* unavailable */)?)?;
let image = decode_vtex_c(&bytes)?; // Image { width, height, rgba }
let candidates = hero_portrait_path("npc_dota_hero_lion");
```

- VPK v2 signature/header and extension/path/name tree parsing, CRC, preload
  metadata, numbered archive selection, and `0x7FFF` directory-file data.
- Seek plus exact bounded entry reads, including preload bytes, with CRC32
  verification. Missing files, corrupt/truncated inputs, foreign entries, and
  out-of-bounds sections return errors. Reads have a 256 MiB entry limit.
- Source 2 resource header version 12, relative block-table and block offsets,
  VTEX version 1, 2D depth 1 and one mip. The relative-offset regression test
  caught the round-1 assumption about the DATA table position; it is fixed.
- RGBA8 output from DXT1, DXT5, embedded PNG (observed format codes 16/18), and
  raw RGBA8888 (observed code 28). PNG decoding supports 8-bit grayscale, RGB,
  palette, grayscale-alpha and RGBA, filters 0-4, palette transparency, CRC and
  bounded zlib inflation; interlaced/16-bit PNG is unsupported.
- No runtime BC7, ATI2, JPEG, LZ4, multi-mip, cubemap, volume or animated texture
  support. Unsupported layouts/formats return errors. BC7 mode-6 known-answer
  construction/decoding exists **only as a synthetic test utility**, and does
  not establish runtime BC7 support; the census did not require it.
- No persistent image cache or host integration is implemented. The library
  opens game files for reading only. The probe is the only image writer.

`flate2` 1.1.11, already pinned in the workspace, is the only external crate used
by this package (embedded PNG zlib decoding and probe PNG output). Cargo.lock
adds only `kohbor-game-assets` 0.0.1; every existing package record is unchanged.

## Directory parsing and memory

The 23,322,079-byte directory VPK has a 21,397,095-byte tree. `Vpk::open` streams
the tree through an 8 KiB `BufReader`; it does not load the tree or an archive
into a vector. It retains only 554 portrait metadata records and their path
strings. Preload bytes are not retained in the index: `read` seeks to their tree
position and reads them when needed. Other paths use a bounded tree rescan;
portrait lookups use the retained index.

Thus the 21.4 MB tree is not a RAM requirement; retained directory state is a
small metadata index rather than tens of MB of directory contents. Exact heap
allocation and parse-only peak were not instrumented. Windows reported a total
process peak working set of 5,545,984 bytes (5.29 MiB) after open and 6,270,976
bytes (5.98 MiB) after both images, including executable/runtime pages. These
are process measurements, not an isolated heap figure or whole-app budget.

## Host recommendation

| Use | Preferred directory | Reason and qualification |
| --- | --- | --- |
| Own-hero card, approximately 64 px square tile | `selection/` | Normally 142x188: enough resolution for an explicit square crop and downsample to 64x64. The UI must choose the crop/fit; this spike does not approve a visual crop. `icons/` is already cropped square but only 32x32, requiring 2x enlargement; reserve it for native 32 px use or an explicit lower-resolution fallback. The root's 128x72 image can supply a 72x72 crop, but gives less crop headroom. |
| Draft-bar identity reference, approximately 119x65 screen box | heroes root | Common 128x72 portraits have aspect 1.778 versus screen box 1.831, with adequate native resolution and only modest resize/crop adjustment. Selection portraits are upright (142x188, aspect 0.755); icons are square and low-resolution. Use the root reference with separately verified box alignment/normalization; matching accuracy and actual screen composition remain unverified. |

Reuse the game root selected by existing GSI setup discovery: `intake.rs`
`locate_game`/`find_game` resolves Steam libraries and appmanifest_570, requires a
unique install, and returns the installation root containing `game/dota/cfg`.
Pass that root into the host asset service and join `game/dota/pak01_dir.vpk`;
do not hardcode a Steam library. No intake code was changed.

Recommended host command shape (proposal, not implemented):
`load_local_hero_portrait { hero_id, purpose: own_card | draft_reference }`.
The host derives the install/cache path internally, selects selection/root by
purpose, and returns an image or an explicit unavailable reason. Perform one
lazy/background VPK open and on-demand decoding off capture/audio critical
threads; reuse an in-memory image cache rather than reading the VPK each frame.
Unreadable, missing, stale or unsupported resources keep identity unavailable.

Start with memory-only caching. If measurement later justifies disk caching,
use only the host's established per-user application cache directory, keyed to
the selected install, directory/entry revision and decoder version, and reject
stale/corrupt cache entries. Do not ship generated files or place them in a Git
worktree, fixture, game directory, package or network service. This spike
implements no cache deletion, cloud path, telemetry, game-memory access,
injection, or gameplay input.
